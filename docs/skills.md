## 1. Mental model (5 lines)
- `src/main.ts` wires everything. `game/game.ts` (Game) owns the state machine MENU / CINEMATIC / RACING / PODIUM and the fixed 1/60 s loop; `core/raceManager.ts` runs racers; `physics/carController.ts` steps one car (legacy model in `physics/legacy`, v2 in `physics/v2`, both call `physics/drivetrain.ts`).
- Maps are DATA (`data/tracks/*.ts` TrackDef polygon with fillets) -> `buildTrack` -> `world/` builds meshes, `physics/` uses the same samples, the minimap draws them.
- UI is plain DOM layers (`ui/*`, classes `rb-layer`, `rb-panel`, `rb-row`; CSS in `ui/menuCss.ts`). Menus are in `ui/menu.ts`, settings in `ui/settings.ts` (Basic / Advanced tabs).
- Saves: `core/save.ts` (SaveStore, localStorage, versioned, `parseSave` in `saveParse.ts`), race snapshots `core/gameSave.ts` + `game/saveGame.ts`. No server, no database: every player's data lives in their browser. Online races are PeerJS peer to peer.
- Strings: `src/i18n/en*.ts` + `es*.ts`, typed keys, `t('key')`; long content uses `tx('English text')` with the Spanish in `esContent*.ts`.

## 2. Hard rules (the build enforces the first)
- Every `.ts` file < 220 lines (`scripts/check-lines.mjs`). At the limit now: `game/game.ts` 219, `core/raceManager.ts` 219, `ui/menu.ts` 219, `main.ts` 217. Do not add lines there: split or put new code in a new module and wire it with one line.
- No `enum` / `namespace` / constructor parameter properties; `import type` for types. No `three` in `src/physics`. Physics in fixed 1/60 steps. No allocation per frame or step (no closures or arrays in `update`/`step`; use methods and reused objects).
- Car space +Z nose, +X left, `steer > 0` is LEFT. Contracts: `src/types/game.ts` (change = architecture change, log it in handoff). Brands only in `data/cars.ts`.
- LOCKED (owner): the turbo model (drivetrain boost, `audio/turboSound`), approved rain/snow physics, STANDARD assist handling, handbrake carry/hold in `physics/legacy/stability`. Ask before touching.
- Money must be paid once per race: `Game.startRace` gives each race `meta.raceId`; `SaveStore.claimRace` (last 16 in `data.paid`) is checked in `game/story.ts finish`. Never bank cash elsewhere.

## 4. Playbooks
- Add a setting: type + default in `core/save.ts` (the long `settings:` line), parse it in `core/saveParse.ts`, apply it in `applySettings` (`ui/settings.ts`), row in `ui/settings.ts` (Basic or Advanced) or `ui/drivingSettings.ts`, strings in `enMenu.ts` + `esMenu.ts`. Run `npx tsx tests/i18n-check.mts`.
- Add a string: key in BOTH `i18n/enX.ts` and `i18n/esX.ts` (typed `t()` keys; template keys need a literal array or a cast). Content text for `tx()`: add the Spanish to an `esContent*.ts`. `tests/i18n-check.mts` fails on any gap.
- Add a track (data only): copy `data/tracks/driftRing.ts`; vertices are corners `{x,z,r,zone,w}` (r = fillet, must fit half the legs: tangent length = r*tan(turn/2)); `type` circuit | sprint | drift (drift needs `driftTarget`); min length 1000 m (sprint 1800); register in `index.ts`, add a palette, add the ES blurb. Check: `npx tsx tests/tracks-check.mts`, `tests/city-check.mts`. Probe drift scores with the bots in `tests/lab/laps.mts` (copy it, read `car.drift.bank + car.drift.chain`).
- Add an input action: optional field on `CarInput` (contract), every source sets it, `CombinedInput` ORs it, consumed in `physics/legacy/legacyStep.ts` AND `physics/v2/v2Step.ts`.
- Add a touch button: create with `tag(holdButton(...), 'id')` in `ui/touchControls.ts`, add the id to `IDS` in `ui/touchLayout.ts`, CSS in `touchButton.ts`.
- Add a cutscene: copy an entry in `data/cutscenes.ts` (coordinates are metres around the stage, the car at 0,0; +Z is the car's nose), keep captions inside the total shot time and not overlapping, add the Spanish for every text, reference it from `StoryEvent.cutBefore`; `npx tsx tests/cutscene-check.mts`. ## 6. Server, deploy, git
- Live site: https://notcarlos.mosidealus.nl (docroot `/data/www/carlos.mosidealus.nl/public_html`, nginx vhost is Ansible-managed: never edit). Deploy: `tsh login` first (the session expires, error "cert has expired"), then `scripts/deploy-server.sh` (it logs in as `webdev@`; root also works). It wipes the docroot and unpacks `dist`.
- The server firewall (ufw) was closed to the public; ports 80/443 were opened 2026-11-18. If the site only works from the company network again, check `ufw status`.
- Storage (since 2026-11-19): player progress lives in MySQL on the server, not in the browser. Browser: `src/boot.ts` (entry in index.html) pulls the player's data (2.5 s max) then imports `main.ts`; `core/serverSync.ts` hooks `Storage.prototype.setItem/removeItem` for the synced keys (`SYNC_KEY`: `racers-blood-save-v1`, `racers-blood-slots`, `ns.ach`, `ns.stats`, `ns-online-name`, `rb-ghost:*`) and uploads changes 1.5 s later; the browser keeps a cache and the player code (`rb-player`, 20 base32 chars, shown in Settings > Advanced > Game with Copy / Use another code). Device-only keys (`rb-controls`, `ns.keys`, `rb-howto`, tier/phone defaults, `rb-sync-ts`, `rb-sync-dirty`, `rb-player`) are NOT synced. Launch cost: the first pull is full; after it the browser keeps the server time (`rb-sync-ts` = `now` - 2 s) and asks `GET ?since=<ts>`, so the server (index-free scan of the player's rows by `updated`) returns only keys changed since (nothing new = ~28 bytes); a key DELETED on another device is not noticed by incremental pulls (deletes are rare; switch player code or clear data to resync). Responses are gzip-compressed by `storage.php` (nginx does not compress JSON here), uploads over 20 KB are gzip-compressed by the browser (`Content-Encoding: gzip`, decoded with a size limit). Measured 2026-11-20 with a realistic 444 KB player (save, 5 slots, 8 ghosts): full pull 526 KB / 0.45 s plain, 221 KB / 0.41 s gzip, incremental 28 B / 0.23 s (mostly TLS setup), upload 444 KB -> 144 KB. A database cannot raise the game's frame rate (that is the browser's GPU work); it only removes storage/network cost. Offline or no API (GitHub Pages, phone app): runs on the cache, `rb-sync-dirty` remembers unsent keys and local changes win on the next pull. To sync a new key: add it to `SYNC_KEY` in `core/serverSync.ts` AND `KEY_RE` in `server/api/storage.php`.
- Server side: `server/api/storage.php` (PHP 8.3-FPM, PDO, GET = all keys, POST `{items:{key:value|null}}`, header `X-Player`, only sha256 of the code is stored, 400 KB per key, 4 MB per player), deployed by `scripts/deploy-server.sh` into `/api/`. Database: its OWN MySQL 8.0 instance (Percona build, single node) `neonspeed-mysql.service`, 127.0.0.1:3307, datadir /var/lib/neonspeed-mysql, config /etc/neonspeed-mysql/my.cnf (64 MB buffer pool, ~160 MB RSS), DB `neonspeed` (tables `players`, `player_kv`, schema in `server/db/schema.sql`), app credentials in /etc/neonspeed/db.php (root:webdev 0640: the FPM workers run as group webdev, NOT www-data), root client config /etc/neonspeed-mysql/root.cnf. Rebuild or repair it with `scripts/setup-server-db.sh` (idempotent). The old Percona XtraDB Cluster unit `mysql.service` (Galera node, peer 10.233.77.70, dead since August) is DISABLED; its data in /var/lib/mysql was not touched. AppArmor: local override lines added to /etc/apparmor.d/local/usr.sbin.mysqld. Test the API with curl: `curl -H "X-Player: ABCDEFGHIJKLMNOPQRST" https://notcarlos.mosidealus.nl/api/storage.php`. Local dev against the real server: `RB_API=https://notcarlos.mosidealus.nl npm run dev`. Test: `tests/server-sync-check.mts` (fake server).
- Feedback and donations (2026-11-19): `ui/feedback.ts` (Crew > Feedback & support, also Settings > Advanced > Game) posts to `server/api/feedback.php`, which ALWAYS stores the message in table `neonspeed.feedback` and then tries `mail()` (Postfix is running; mail from this IP may land in spam, so the DB row is the record). The recipient is NOT in git or in the game: it lives in /etc/neonspeed/feedback.php, set by the owner with `FEEDBACK_EMAIL=<address> scripts/set-feedback-email.sh` (the privacy guard blocks agents from typing that address, so the owner runs it with `!`). Read what people sent: `scripts/read-feedback.sh [count]`. Limits: 5-2000 chars, honeypot field, 40/hour and 200/day GLOBAL (all visitors share one NAT address). Donation details (IBAN, voluntary) are in `data/support.ts`; the IBAN is checked by `ibanValid` in tests/feedback-check.mts, so a typo fails the build's tests.
- Redis (decision 2026-11-20, not installed): not needed. Measured server time per storage request is ~50 ms and the network dominates; MySQL on localhost already serves the per-player key-value reads. Revisit if (a) global leaderboards reach thousands of players (Redis sorted sets), (b) we replace the public PeerJS broker with our own lobby / relay server (pub/sub), or (c) rate limits need to be per real client (they are global today because every visitor shares one NAT address). For tiny caches without a daemon use PHP APCu first.
- Git: push after every block. This machine has no global git identity: commit with `git -c user.name=Carlos -c user.email=<owner email from earlier commits> commit`. Commit messages end with the Co-Authored-By line. Qwen branches `qwen/<task>` merge only through `/review-qwen`.

## 7. Known gotchas (cost me time once)
- CSS `hidden` is overridden by `display:grid/flex`: add `[hidden]{display:none!important}` (see `.rb-tabs`).
- Individual CSS `translate` / `scale` are used on touch buttons so the press `transform` still works.
- Typed i18n: `t(\`how.t${i}\`)` fails to compile; index a `as const` array instead.
- `Game.startRace` mutates `setup.meta` (raceId): do not reuse a meta object between races.
- Visual look bugs: bright HDR emissive (multiplier > 2) on long meshes washes out through bloom; keep strips near 1.2-1.6.
- Labs that `import()` source files inside the dev page: Vite adds `?t=<edit time>` to imports of files edited after the server started, so a bare `/src/x.ts` import can be a SECOND module instance (separate globals such as `MUSIC_SOURCE`). Import the URL from `performance.getEntriesByType('resource')` (see `tests/lab/music-join.mjs`).
- `tests/save-roundtrip.mts` guards the rule "a restored race runs identically": new per-race state must be in the snapshot.
